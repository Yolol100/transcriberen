# Self-hosted Transcriberen runner

This lane exists for public YouTube requests that are blocked specifically by GitHub-hosted cloud egress. It keeps the same Project Transcriberen request contract, resolver, runtime, validator, checksums and evidence semantics; only the network origin of the runtime job changes.

## Required runner

Use a dedicated Linux x64 machine with the custom GitHub Actions label `webactueel-transcribe`.

In the repository, open **Settings -> Actions -> Runners -> New self-hosted runner**, choose Linux x64 and follow the commands GitHub generates for that repository. Add the custom label during runner configuration:

```bash
./config.sh --url https://github.com/Yolol100/transcriberen --token <GITHUB-GENERATED-REGISTRATION-TOKEN> --labels webactueel-transcribe
```

The registration token is generated by GitHub for runner enrollment; it is not a YouTube/API credential and must not be committed to this repository.

After configuration, start the runner with the GitHub-provided `run.sh` command or install the runner as a service using the instructions shown by GitHub for the host.

## Security boundary

This repository is public. A self-hosted runner therefore needs a stricter boundary than the normal GitHub-hosted lane:

- dedicate the host to this runner; do not use a personal workstation with browser profiles, SSH keys, cloud credentials or unrelated project secrets;
- assign the runner the custom label `webactueel-transcribe` and do not reuse that label for unrelated workflows;
- the self-hosted workflow is triggered only by pushes to `runtime-requests-selfhosted`; it has no pull-request or reusable-workflow trigger;
- the GitHub-hosted `resolve` job validates that the transport commit adds exactly one immutable request JSON;
- the self-hosted job never checks out the transport branch; it checks out `Yolol100/transcriberen@main` with persisted credentials disabled;
- the YouTube runtime explicitly removes proxy environment variables before source acquisition;
- cookies, login, CAPTCHA bypass, PO tokens and YouTube media download remain forbidden;
- keep the machine patched and remove/disable the runner immediately when it is no longer needed.

A persistent self-hosted runner is not an ephemeral clean VM. Repository controls reduce exposure but do not replace host isolation and GitHub account/ruleset administration.

## Request transport

After the runner shows **Idle/Online** in GitHub, create exactly one new request per commit under:

```text
requests/queue/<request_id>.json
```

on branch:

```text
runtime-requests-selfhosted
```

The workflow publishes the status context:

```text
runtime/Transcribe Public Source Self-Hosted
```

Validated results are uploaded as:

```text
transcription-result-<request_id>-self-hosted
```

## YouTube smoke test

Use the same request JSON that previously returned `access_blocked` on the GitHub-hosted lane. A successful comparison requires actual transcript or comment evidence; a green workflow by itself is only infrastructure evidence.

## Rollback

The existing `runtime-requests` GitHub-hosted route remains unchanged. To disable this lane without affecting it, stop/remove the self-hosted runner or stop writing requests to `runtime-requests-selfhosted`. Reverting the self-hosted workflow commit removes the repository-side route.
